# Приглашение на свидание

Розово-фиолетовая интерактивная открытка: согласие → дата → время → подтверждение доставки в Telegram → финал. Существующие SVG-котики, эффекты и мобильная адаптация сохранены. Экспорта .ics нет.

## Структура и запуск

Frontend без сборки находится в `public/`, Pages Function — в `functions/api/respond.js`. `server/` содержит серверную валидацию и D1-хранилище. Node.js 22 или новее; npm-пакеты не требуются. Wrangler 4 используется как отдельно установленный инструмент Cloudflare, в lockfile нет сторонних зависимостей.

```sh
npm ci
npm test
npm run build
npm run preview:local
```

Локальный адаптер открывает http://localhost:8080 и не имитирует доставку. Для полного runtime с Functions и D1 используйте установленный Wrangler: `npm run dev`. Без серверных настроек отправка закрыта, а кнопка подтверждения недоступна без Turnstile.

## Настройка одной инсталляции

Имя отправителя задаётся в начале `public/script.js` (`CONFIG.senderName`) и в `wrangler.toml` (`SENDER_NAME`); проверка build требует совпадения. `girlName` может быть пустым. `CONFIG.turnstileSiteKey` — публичный ключ виджета Cloudflare Turnstile, не секрет. Создайте виджет для hostname своего Pages-сайта, используйте compact/dark, action `date_response`. Секрет виджета хранится только на сервере.

Для постоянной публикации создайте Cloudflare Pages-проект, подключённый к этому GitHub-репозиторию. Production branch: main. Build command: `npm run build`. Output directory: `public`. Functions включаются из корневой папки `functions`; не публикуйте только статическую папку отдельно. Бесплатного pages.dev достаточно.

Создайте D1-базу `date-invitation-state`. В `wrangler.toml` добавьте фактическую секцию `[[d1_databases]]` с binding `DB`, database_name созданной базы, её настоящим database_id и migrations_dir `migrations`. UUID не является секретом, но его нужно получить в своём аккаунте, а не копировать чужую конфигурацию. Примените `wrangler d1 migrations apply date-invitation-state --remote`. Привяжите ту же базу как DB к Pages production и отдельно к preview, если preview используется. Wrangler-конфигурация должна совпадать с привязками Pages.

Через безопасные поля Cloudflare Pages Settings → Variables and Secrets добавьте encrypted secrets:

- TELEGRAM_BOT_TOKEN
- TELEGRAM_CHAT_ID
- TURNSTILE_SECRET_KEY

Не вводите значения в команды, README, Git, чат или URL браузера. Ранее раскрытый токен нужно сначала отозвать через `/revoke` в @BotFather. Новый токен вводится владельцем непосредственно в безопасное поле. Откройте своего бота и нажмите Start. Получатель фиксируется сервером; клиент не может назначать chat_id или произвольный текст.

Локально допустим только исключённый из Git `.dev.vars`, пример с пустыми значениями — `.dev.vars.example`. `node scripts/resolve-chat.js` получает getUpdates с токеном из этого файла, не печатает токен, URL, chat ID или сообщения; предлагает выбрать приватный чат по имени и записывает chat ID в `.dev.vars`. После выбора может отправить одно тестовое сообщение. Не используйте раскрытый токен. Предпочтительно настройте секреты прямо в Cloudflare.

После настройки ключа, D1 и secrets запустите тесты, build и публикацию Git-интеграцией Pages либо `npm run deploy` с авторизованным Wrangler. Проверяйте реальный HTTPS hostname, не временный cloudflared Tunnel. Не публикуйте форму без настроенной защиты и получателя.

## Поведение и ограничения

Даты: 5–31 октября 2026; время: 10:00–18:30 с шагом 30 минут; зона Europe/Kyiv. Уже прошедшие дни недоступны на клиенте и сервере. После 31 октября приглашение истекает: владелец должен обновить диапазон, календарь и тесты до повторного использования.

`responseData` сохраняет ровно accepted, date, time, senderName. POST добавляет UUID requestId и Turnstile token. Данные не отправляются при простом выборе даты. Финал появляется только после успешного Telegram API ответа с message_id. API возвращает общие коды ошибок без upstream-описаний и секретов.

Защита: строгая схема, тело до 4096 байт, проверка Origin плюс обязательная серверная проверка Turnstile (hostname/action), 5 обращений за 10 минут на хеш IP, фиксированный серверный получатель. D1 атомарно фиксирует запросы и координирует конкурирующие Functions. Один UUID сохраняется при повторе того же выбора и в sessionStorage текущей вкладки. Успешный запрос повторно не отправляется. Явный отказ Telegram допускает повтор; timeout/неоднозначный ответ сохраняется как uncertain и автоматически не пересылается. Exactly-once не гарантируется: при uncertain владельцу нужно сверить Telegram и запись D1 вручную. Новая вкладка/новый выбор создаёт другой запрос; ограничения и Turnstile сдерживают злоупотребления, но не заменяют идентификацию приглашённого человека.

D1 хранит UUID, хеш выбора, статус и время; rate_limits хранит хеши, не исходные IP. Старые rate buckets очищаются автоматически; записи submissions следует удалить вручную после закрытия приглашения. Это отдельный сайт одного отправителя, а не сервис регистрации и создания чужих приглашений.

## Проверки

`npm test` проверяет все 486 сочетаний диапазона, дни недели, единственность выбора, отказ и возврат, reduced-motion, блокировку кликов, успешный и ошибочный API, таймаут, схему, Origin, размер тела, истечение по Kyiv, Turnstile, rate limit и конкурентную идемпотентность на настоящем SQLite с SQL миграции D1. Upstream в тестах подменён, тесты не отправляют реальные сообщения.

`npm run build` проверяет структуру, ссылки/ID, версии ресурсов, отсутствие экспорта календаря, публичных Telegram-секретов и рассогласования имени. CSS/JS используют новую версию URL; HTML и API — no-store. Не подключены внешние изображения, музыка или шрифты. Единственная внешняя клиентская зависимость — требуемый защитный виджет Turnstile.

До завершения публикации отдельно обязательны: smoke test Functions/D1 в Cloudflare, реальный тест доставки владельцу, проверка HTTPS и визуальная проверка Safari на iPhone. Автоматические DOM-тесты и анализ CSS не подтверждают испытание на реальном устройстве.
